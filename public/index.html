How a payment flows

              
    
                
  1. Portal sends a signed request to DigiCash
    2.

    3. 
                
  3. Customer opens the link and pays
    4.

Why does the portal proxy requests?

              
Your browser never holds the secret key. The portal server signs each request securely and forwards DigiCash's answer back to this screen.

SVI DigiCash — DigiCash API Integration

              
Ticket CPS-471 · Payment gateway POC · Production: api.fastpayph.com · Merchant: service.svi

              

                
 Goal
Collect payments (e-wallets, QR) and disburse payouts (InstaPay) through DigiCash.

                
 Status
Integration proven end-to-end up to DigiCash. Blocked on their provider config + wallet funding.

              

            


            

              
How money moves

              
DigiCash is the middleman between us, the provider, and the banks.

              
flowchart LR
    C[Customer] <-->|pays / receives| D[DigiCash API]
    D <-->|forwards to| P[Upstream provider]
    P <-->|settles with| B[Banks and wallets]
    S[SVI merchant service.svi] <-->|signed requests + callbacks| D

              

                
 DigiCash (gateway)
The company and API we integrate with. Checks our signature, routes the money, notifies us of results. Think: the bank branch.

                
 Upstream provider
The company behind DigiCash that physically moves money. We never talk to it directly. Think: the armored van.

                
 Bank / wallet
Where money starts or ends (GCash, Maya, BDO…). Holds the funds — different from the provider that carries the transfer.

                
 Merchant (us)
Our DigiCash account (service.svi): credentials plus a prefunded wallet that payouts draw from.

              

            


            

              
The 4 APIs

              
Three we call, one that calls us.

              

                
POST /pay
Start a customer payment → returns a payment-page link.

                
POST /payout
Send money to any bank/wallet via InstaPay.

                
POST /status
Ask what happened to any transaction.

                
POST → callback
DigiCash pushes PAID / FAIL / EXPIRED to us.

              

              
Pay vs payout — don't mix them up

              

                
Pay (money in)Payout (money out)

                
DirectionCustomer → usUs → customer

                
Who actsCustomer pays on a DigiCash pageWe push to their bank / wallet

                
MethodsGCash, PalawanPay, QRPh, QRPh VIPInstaPay (92 banks & wallets)

                
Money comes fromCustomer's walletOur prefunded DigiCash wallet

                
Typical useCheckout, top-up, collectionDisbursement, salary, refund

              

            


            

              
Security & signing

              
Every request carries three credentials plus a signature. Secrets never leave our server.

              

                
CredentialValueMeaning

                
service_idservice.sviOur merchant account

                
passwork••••••Merchant password (server only)

                
secret_key•••••• (30 chars)Signing key (server only, never committed)

              

              
    
                
  1. Concatenate field values in body order (skip signature)
    2. 
                
  2. Empty value becomes -
    3. 
                
  3. HMAC-SHA256 with the merchant secret_key
    4. 
                
  4. Attach the hex digest as signature
    5. 
              

              
Example — a ₱1.00 GCash payment signs this exact string

              
service.svi + [passwork] + 100 + PHP + <operation_id> + <payment_id> + gcash + <callback_url> + <return_url>

              
Field order per endpoint (proven by live probe)

              

                
EndpointSigning order

                
Payservice_id, passwork, amount, currency, operation_id, payment_id, by_method, callback_url, return_url

                
Payoutsame as Pay, then customer{account_bank_id, account_number, account_name, email, phone_number}

                
Statuspasswork, service_id, request_id (passwork first)

              

            


            

              
Pay flow

              
Methods: QRPh · QRPh VIP (GCash & PalawanPay discontinued by DigiCash). Amounts in centavos as strings (₱100 → "10000").

              
flowchart LR
    A[Portal sends SIGNED request] --> B[POST /pay]
    B --> C{Gateway signature OK?}
    C -- No --> E[HTTP 400 code 2041]
    C -- Yes --> F[Forward to provider]
    F --> G{Provider accepts?}
    G -- No --> H[operation FAIL + message]
    G -- Yes --> I[redirect_url for customer]
    I --> J[Customer pays]
    J --> K[Callback PAID / FAIL / EXPIRED]

              
Step by step

              
sequenceDiagram
    participant U as Portal UI
    participant S as Portal server
    participant D as DigiCash
    participant P as Provider
    participant C as Customer
    U->>S: Pay ₱100 via QRPh
    S->>S: Sign request (Section 4)
    S->>D: POST /pay
    D->>D: Verify signature
    D->>P: Forward payment
    P-->>D: Accept
    D-->>S: 200 + redirect_url + request_id
    S-->>U: Show link + Request ID
    U->>C: Customer opens link & pays
    P->>D: Money moved
    D->>S: POST callback: PAID
    S->>S: Verify + log + display

Statuses

              
Responses use lowercase, callbacks use UPPERCASE. PAID / FAIL / EXPIRED are final.

              

                

              
stateDiagram-v2
    [*] --> awaiting_redirect : pay created
    [*] --> initiated : pay/payout created
    awaiting_redirect --> processing : customer pays
    initiated --> processing : provider works
    processing --> paid : money moved
    processing --> fail : rejected
    processing --> expired : window lapsed
    paid --> [*]
    fail --> [*]
    expired --> [*]

                

                

                  

                    
StatusWhere seenMeaning

                    
awaiting_redirectPay responseWaiting for the customer to open the payment page

                    
initiatedPay/Payout responseTransaction created, waiting

                    
processing / PROCESSINGResponse / callbackBeing processed

                    
paid / PAIDResponse / callback Money moved — final

                    
fail / FAILResponse / callback Rejected — final, read the provider message

                    
expired / EXPIREDResponse / callback⏰ Payment window lapsed — final

                  

                

              

            


            

              
Errors — which layer failed?

              
Gateway errors are ours to fix. Provider errors are DigiCash's.

              

                
CodeMeaningOwnerStatusAction

                
2041Our signature rejected — gateway HMAC check failedOursFixed — 7-variant live probe (2026-09-07): only the Postman field order passes; every other order is correctly rejectedNone — recheck only if signing code or secret changes

                
2043Unknown merchant — service_id not registered in that environmentOursResolved — seen only on UAT; production accepts service.svi since the move to api.fastpayph.comNone — keep base URL on production

                
3011Provider failedDigiCashOpenEscalate; awaiting their fix

                
7015Wallet emptyDigiCashOpenAwaiting wallet funding
