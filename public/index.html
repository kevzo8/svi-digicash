Endpoints (production)

POST /payCollect a payment (e-wallet or QR)
POST /payoutSend money out via InstaPay
POST /statusCheck a transaction's status
POST → callbackDigiCash notifies us: PAID, FAIL, etc.

How a payment flows

  1. Portal sends a signed request to DigiCash
  2. DigiCash returns a payment page link
  3. Customer opens the link and pays
  4. DigiCash calls our callback with the result

Why does the portal proxy requests?

Your browser never holds the secret key. The portal server signs each request securely and forwards DigiCash's answer back to this screen.

How money moves

DigiCash is the middleman between us, the provider, and the banks.

flowchart LR
    C[Customer] <-->|pays / receives| D[DigiCash API]
    D <-->|forwards to| P[Provider Starpay]
    P <-->|settles with| B[Banks and wallets]
    S[SVI merchant service.svi] <-->|signed requests + callbacks| D

The 4 APIs

Three we call, one that calls us.

POST /pay

Start a customer payment → returns a payment-page link.

POST /payout

Send money to any bank/wallet via InstaPay.

POST /status

Ask what happened to any transaction.

POST → callback

DigiCash pushes PAID / FAIL / EXPIRED to us.

Security & signing

Every request is HMAC-SHA256 signed. The secret never leaves our server.

  1. Concatenate field values in body order (skip signature)
  2. Empty value becomes -
  3. HMAC-SHA256 with the merchant secret_key
  4. Attach the hex digest as signature

Pay flow

Methods: GCash · PalawanPay · QRPh · QRPh VIP. Amounts in centavos as strings (₱100 → "10000").

flowchart TD
    A[Portal sends SIGNED request] --> B[POST /pay]
    B --> C{Gateway signature OK?}
    C -- No --> E[HTTP 400 code 2041]
    C -- Yes --> F[Forward to Starpay]
    F --> G{Provider accepts?}
    G -- No --> H[operation FAIL + message]
    G -- Yes --> I[redirect_url for customer]
    I --> J[Customer pays]
    J --> K[Callback PAID / FAIL / EXPIRED]

⚠️ Wallet funding

Empty wallet returns code 7015. DigiCash must top up merchant service.svi before payouts can complete.

Statuses

Responses use lowercase, callbacks use UPPERCASE. PAID / FAIL / EXPIRED are final.

stateDiagram-v2
    [*] --> initiated
    initiated --> processing
    processing --> paid
    processing --> fail
    processing --> expired
    paid --> [*]
    fail --> [*]
    expired --> [*]

Errors — which layer failed?

Gateway errors are ours to fix. Provider errors are DigiCash's.

CodeMeaningAction
2041Our signature rejectedFix signing
2043Unknown merchantCheck service_id / environment
3011Provider failedRead provider message; escalate to DigiCash
7015Wallet emptyFund merchant wallet
